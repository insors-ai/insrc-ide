insrc CLI Design Document

Overview

Design document for the insrc CLI — equivalent functionality to the VS Code extension. 5 of 5 requirements addressed.

Requirements Summary

  • [FUNCTIONAL] The CLI shall support all core functionalities available in the VS Code plugin, including intent classification, local LLM execution, and Claude API routing — with command-line options for specifying intent (--intent), forcing Claude routing (--claude), outputting JSON (--json), and setting the working directory (--cwd) — DONE
  • [FUNCTIONAL] The CLI shall support structured JSON output for programmatic consumption — DONE
  • [SYSTEM] The CLI shall connect to a locally running insrc daemon via IPC channel for all agent operations — DONE
  • [SYSTEM] The CLI shall handle daemon initialization, including installation, Ollama detection, model pulling, and first-run API key configuration — DONE
  • [SYSTEM] The CLI shall support all Claude model variants (Haiku, Sonnet, Opus) with metrics tracking, caching, and rate limiting when Claude routing is enabled — DONE

    • Requirement 1: The CLI shall support all core functionalities available in the VS Code plugin, including intent classification, local LLM execution, and Claude API routing — with command-line options for specifying intent (--intent), forcing Claude routing (--claude), outputting JSON (--json), and setting the working directory (--cwd)

    2. DATA FLOW

  • ENTRY: CLI receives insrc ask [options]

    • - Arguments parsed into AskOpts structure by existing parser in /src/cli/index.ts

  • INIT: WorkingDirectoryResolver validates --cwd option

    • - Calls validateCwd(cwd) from /src/cli/resolvers/working-dir-resolver.ts - Sets process.cwd() or throws error if invalid

  • CLASSIFICATION: If intent NOT overridden (AskOpts.intent is null):

    • - Calls classify(message) from /src/agent/classifier/index.ts - Returns ClassifyResult with primary intent - Extracts primaryIntent from result

  • ROUTING: Routing decision logic:

    • - If AskOpts.claude=true: Use Claude routing - Else if isClaudeDefault(primaryIntent, config): Use Claude routing (fallback) - Else: Use local agent routing

  • EXECUTION: Execute one-shot operation:

    • - Calls runOneShot(message, OneShotOpts) from /src/agent/cli.ts - OneShotOpts = { intent: primaryIntent, claude?: AskOpts.claude } - [CRITICAL] Must ensure session initialization via initializeSession(cwd) before this call - Returns OneShotResult with output and metadata

  • FORMAT: Output formatting:

    • - If AskOpts.json=true: - Calls JsonOutputFormatter.format(OneShotResult) from /src/cli/formatters/json-output-formatter.ts - Returns JSON string - Else: Pretty-print to console using default formatter

  • OUTPUT: Write result to stdout and exit with code 0

  • RPC Implementation (src/cli/client.ts)

  • Daemon Server Reception (src/daemon/server.ts)

  • Daemon Execution (src/daemon/chat-handler.ts)

    • - Executes intent classification and LLM processing - Uses DaemonChannel to emit progress/delta/checkpoint messages back to CLI - On completion, emits final 'done' message with result data

  • CLI Response Collection (src/cli/client.ts)

    • - Accumulates streaming messages from daemon - Reconstructs structured output when --json flag is set - Resolves Promise with final result on 'done' or rejects on 'error'

  • CLI Output Formatting

    • - If --json: converts result to structured JSON and prints - Otherwise: pretty-prints to stdout - Exits with appropriate code (0 for success, non-zero for error)
